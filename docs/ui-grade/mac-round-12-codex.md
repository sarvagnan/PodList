# PodList Mac — round 12, independent Codex grade

## Frame

- **Task:** Find podcast Episodes, organize them into Views and ordered Playlists, and listen while retaining per-Playlist Positions and recovery history.
- **Target:** Native Mac app, macOS 26+; evidence captured in a macOS 27.2 VM. Source baseline `0652f0b`.
- **Posture:** Sovereign personal library with background playback and transient editing/discovery tasks.
- **Audience:** Perpetual intermediate, with newcomer help and automation routes for experts.
- **Nearest exemplar:** Things for calm personal organization, persistent selection and forgiveness; BBEdit for complete menus and semantic automation. Neither is a visual template.
- **Character:** Compact source-list → table → Inspector organization; typographic podcast-initial artwork; explicit Episode/Entry/Position vocabulary; a persistent bottom transport (**owner-fixed**); restrained blue identity and selective functional Liquid Glass (**owner-fixed adoption**).

**Owner decisions:** Grade the bottom player, dark selected Settings accent and deferred Spotlight normally, including their caps; do not target reversing those choices. AccentColor participates in Multicolor and other accent choices remain system-owned. System/Light/Dark Appearance, no customizable toolbar, the timed two-click unsubscribe control with Undo, selective glass, App Intents on and MCP off by default are accepted constraints. No prior grading reports or grading log were opened. The repository's automatic Beads context included owner-decision summaries; these were not used as grading evidence. No app was built or launched, no desktop/browser/device control was used, and no code was changed.

### Failures by severity

**Blocker**

- **MENU-02 — Failed-drop Remove is absent from the menu bar.** Playlist:140–152 renders a per-slot `Remove` that calls `EpisodeDrop.remove`. Menu:7–37/105–145 indexes only Retry Failed Episode Drop; Editing:302–305's Remove from Playlist uses committed Episode IDs and a different mutation. Transfer:205 onward distinguishes placeholders from Entries. The full menu capture has no failed-drop removal command. This error state was not captured; this is a **C + menu inventory** finding, not a claim that the tour encountered it. **Fix:** expose the same removal operation in Episode, dimmed when unavailable, with explicit failed-slot targeting (or a clearly named Remove Failed Episode Drops command if it intentionally removes all). Keep row buttons and menu validation backed by the same operation. **Principle:** `discoverable-commands`. Platform fit cap **4.9**. Do not “fix” this by deleting useful recovery UI.

**Majors**

- **DLG-08 — Repeated discovery uses an ordinary window rather than the specified utility panel.** App:66–68 declares a normal SwiftUI `Window`; Discovery retains query/results for repeated searching and subscribing while Library stays usable. S24 has ordinary active minimize/zoom controls in XCUI. There is no NSPanel/hidesOnDeactivate configuration in the source. Modelessness is already correct; the failed part is the standard's panel lifecycle/utility treatment. **Fix:** host this repeated discovery task in a titled, draggable modeless panel that hides on app deactivation and returns on activation, preserving its existing query/results/drafts and menu routes. Avoid making it a blocking sheet. **Principle:** `user-control`. Platform fit cap **6.9**, superseded by MENU-02.
- **WIN-05 — Essential transport lives at the window's bottom edge.** S01–23/25/33/34 show the persistent bottom transport; Window and Player place playback/seek there rather than limiting the bottom bar to status. **Owner-fixed; not a target.** A standards-compliant alternative would keep essential transport above the bottom edge and reserve that bar for status, but no relocation is proposed in this audit. **Principle:** `content-first`. Platform fit cap **6.9**, superseded by MENU-02.
- **APPEAR-04 — Dark selected Settings label fails reading contrast.** S30 Dark shows enabled Automation text in blue over the gray selected toolbar tile. Original PNG sampling of region x=665..824, y=115..154 px yields opaque glyph ink **#435FDD** and adjacent tile **#4B4846**: **1.69:1**, below 4.5:1. This is rendered pixel color, not an assumption that the asset's nominal #3652D0 is the final ink. S27–29 show the same selected-label treatment. Accent assets and Settings scene identify the source. Other important custom pairs fare well: white / nominal dark selection #3652D0 **6.41:1**; readable-secondary #606060 / white **6.29:1**. **Owner-accepted; not a target.** A compliant label would need a foreground reaching 4.5:1 on that tile while preserving selected-row readability; the owner has accepted the current tradeoff. **Principle:** `accessibility`. Color & contrast cap **6.9**.
- **SYS-05 — Library content has no Spotlight index.** Intents exposes searchable semantic entities inside automation, but neither app source nor bundle packaging contains Core Spotlight indexing of Episodes/Playlists. S30's automation explanation does not provide system search indexing. **Owner-approved deferral to last; not the next target.** **Fix at the approved stage:** index stable Episode/Playlist identifiers with title, podcast and appropriate metadata, handle open/deletion, and honor release-only indexing. OPML is an imported interchange format; no proprietary-document thumbnail requirement is invented. **Principle:** `discoverable-commands`. Platform fit cap **6.9**, superseded by MENU-02.

**Minors**

- **APP-01 — About has no supplied copyright information.** The menu capture has the correct About PodList group, and bundle packaging supplies version fields, but neither that generated bundle metadata nor the app source supplies `NSHumanReadableCopyright` or a custom About copyright. **Fix:** add the appropriate copyright string to the app bundle metadata used by the native About panel. **Principle:** `conventions`.
- **DATA-05 — Undo does not reveal restored offscreen content.** Edit model:107–144 reverses the database edit, sets an “Undone…” notice and reloads; it emits no restored-Entry selection/reveal target. Window's scroll restoration preserves the previous anchor, and Rows scrolls to that anchor. Restoring a removed Entry outside the viewport therefore has no explicit reveal path. S06/S07 establish the destination list; no Undo-completion capture is supplied, so this finding rests on C. **Fix:** carry affected IDs with the successful Undo result to the initiating window and reveal the restored item without disturbing unrelated windows. **Principle:** `feedback`.
- **HELP-02 — Supplementary help lacks its separating group.** Menu capture lists PodList Help and Getting Started directly adjacent. App:61–64 adds both without a Divider. The system search field is present; its runtime search result is not fabricated. **Fix:** insert the standard separator before Getting Started. **Principle:** `hierarchy`.
- **SYS-02 — No purpose-specific Service for a selected feed address.** Bundle packaging has no NSServices provider and source has no service handler. Receiving selected feed text from another app is relevant to Discovery's feed-address workflow (S24); consuming the system Services menu is a different check. **Fix:** offer an Add Podcast from Feed Address Service that stages the existing discovery/preview route and validates the selection. **Principle:** `conventions`.
- **SYS-03 — Saved app content cannot be linked back into PodList.** App:42–45 handles OPML files only; bundle packaging has no app URL scheme/universal-link registration. Links shares publisher/enclosure URLs, not stable PodList View/Playlist/Episode destinations. S05/S06/S15 show addressable saved contexts. **Fix:** provide stable app-content URLs with validated routing that opens the destination without starting playback. **Principle:** `user-control`.
