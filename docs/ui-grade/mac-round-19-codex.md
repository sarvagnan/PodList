# PodList Mac UI grade · round 19

## Frame

- **Task** — Find an Episode in the Library, inspect it, queue it in the intended Playlist, and listen or resume with confidence about what plays next.
- **Target** — Native macOS app, SwiftUI with AppKit bridges, commit `f166ec9`.
- **Era** — macOS 27.2 (26B123), built against SDK 26.0 with minimum OS 26.0 and no compatibility opt-out. Current build. 2× Retina, Light and Dark selected in PodList. Reduce Transparency and Increase Contrast off in the captures. Show Borders on in the focused pass.
- **Posture** — Sovereign personal library, with transient Add Podcasts and Now Playing windows and background playback.
- **Audience** — Perpetual intermediate. A familiar listener can use the queue immediately and grow into saved filters, multiple Playlists, and Timeline recovery.
- **Nearest exemplar** — Things 3 for calm personal organization, consistent command equivalents, and explicit recovery. Apple Podcasts on macOS 27.2 is the platform reference for show layout and transport.
- **Character** — Text-first Episode tables with bold titles and small show names, saved Views beside independent Playlists, the selected Episode Inspector, the listening Timeline with a rewind preview, and the owner's blue Multicolor accent and glass playback bar.

**Owner decisions.** Graded as shipped. System accent takes precedence over the brand asset. The owner accepts the deep Dark accent on the system Settings tab label, a bottom transport, a fixed toolbar configuration, the tight Playlist toolbar group, three Play entry points plus current-Episode transport, the two-pane rule below 950 pt, and user-controlled sidebar reopening. The Inspector opens at about 270 pt in the tour and remembers a resized width. Saved Views is the menu name. The Podcast page arms Unsubscribe while menus act immediately and both offer undo. Deleted Views and empty Playlists are restored in place without jumping, and the local status row offers Undo only for its own screen. Deleted Playlist Settings stays open with Done and Restore. Timeline Rewind appears on the selected row, with menu and accessibility routes. Sidebar navigation and New Playlist presentation are accepted VM timing misses. App Intents are on, MCP is off by default, and Spotlight and donations follow the measured build policies in the brief. These decisions remain out of target selection.

**Evidence key.** Numbered captures refer to both appearance folders unless qualified. Each has a PNG and an XCUI tree. Source paths prefixed UI are in `apps/apple/Sources/PodListUI`. Neither the app nor any desktop automation was run for this review. ### Blockers

- **FLOW-03 · Late completion clears typed input** — After a Playlist entry removal, start Undo from Edit or the Library status row and type into the still-enabled toolbar Search while reversal is pending. The completion runs through awaited database and refresh work and calls `revealRestoredEntries`. That unconditionally calls `navigate`, whose same-destination branch also sets `search = ""`. The restored entries and Playlist are correct, while text entered during the operation is lost. Screens 10 and 15 identify the Playlist and toolbar Search surfaces. **Fix:** snapshot the originating list and query-edit generation at invocation and honor it at completion. Reveal the restored entries immediately only if the user has stayed in that context without editing the query. Keep the edit result and provide a persistent Show Restored Entries action otherwise. [Undo ordering](/Users/sarvagnan/Documents/PodcastClient/apps/apple/Sources/PodListUI/PlaylistEditingModel.swift:148) · [Library callback](/Users/sarvagnan/Documents/PodcastClient/apps/apple/Sources/PodListUI/MacWindow.swift:311) · [Reveal](/Users/sarvagnan/Documents/PodcastClient/apps/apple/Sources/PodListUI/LibraryModel.swift:388) · [Query reset](/Users/sarvagnan/Documents/PodcastClient/apps/apple/Sources/PodListUI/LibraryModel.swift:463)
- **MENU-02 · Restore Playlist has no corresponding command in its sheet** — In 11a the deleted settings sheet offers Restore Playlist. The Library suppresses its Playlist context for the trashed object, and the Playlist menu’s Restore obtains its handler only from Trash. The settings sheet publishes rename/delete and its Done handler, with no Restore. Edit › Undo Delete Playlist is an edit-history operation and can target a different edit if history has moved. **Fix:** publish the sheet’s `restorePlaylist` as the focused Restore handler when enabled, using the existing Playlist menu item and shared validation.
