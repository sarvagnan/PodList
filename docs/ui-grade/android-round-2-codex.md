### Failures by severity

**Blocker**

- **F01 · DATA-01 — accepted new View is not created.** Where: Views → + → untouched “New View” → Done, including IME Done. Evidence: S05 shows a valid default name, match count and enabled Done. `PodListScreens.kt:271–273` constructs an in-memory View only; `ViewEditor.kt:30–31` initializes `draft` and `saved` to the same value; the sole SaveView call is inside `update` at lines 49–53, reached through editing. Done at lines 59/78 only navigates Back. Accepting the displayed default therefore creates no saved View. This is a deterministic source path; no process-death or interactive reproduction is claimed. **Fix:** ensure an accepted, valid new View is recorded once before completion, even when unchanged, while retaining autosave for subsequent edits. Do not require a meaningless edit or silently dismiss an unsaved accepted draft.

**Major**

- **F02 · FLOW-04 — Add-sheet actions are below the screen.** Where: single/bulk PlaylistAddSheet in its captured partially expanded state. Evidence: `E/light/09-add-sheet.png`, `dark/09-add-sheet.png`, `font200/09-add-sheet.png` show target choices but no Play next/Play last labels. Matching snapshots end with two unnamed button nodes (light @e37/@e39). In original 1344×2992 images the tonal button fill only reaches the bottommost y=2980–2991 (Light/Dark) or 2952–2991 (200%); the labels are below the image. `PlayerPresentation.kt:282–300` gives the inner body half the entire container height, then adds sheet handle/insets around it and allows partial expansion. **Fix:** constrain the entire half-height sheet to its visible safe viewport, account for handle/navigation/IME insets inside that budget, pin the action row inside it, and scroll only the targets. Preserve the owner’s half-height chooser. Whether dragging the sheet higher recovers the buttons was not exercised and does not make the initial follow-up visible. No duplicate WIN-03 or AX-01 failure is charged for this same geometry defect.
- **F03 · DLG-01 — reversible Unsubscribe still interrupts with a confirmation.** Where: Subscription settings. Evidence: `AddPodcastsScreen.kt:111–128` opens AlertDialog before each Unsubscribe, then offers resubscribe Undo; `AppModel.kt:183–200` implements the inverse; Standalone `apps/android/data/src/main/kotlin/app/podlist/data/LibrarySource.kt:77–81` marks the Subscription removed without deleting its stored rows. This is routine recoverable removal, not Empty Trash. **Fix:** retain the consequence copy near the action, perform Unsubscribe directly, and offer its existing Undo/recovery. If a connected-server case can cause genuinely irreversible loss, confine confirmation to that demonstrated case. The owner-fixed immediate Delete Playlist already follows the right pattern.
- **F04 · CTRL-08 — long waits have silent busy surfaces.** Where: playback with the player collapsed, and per-result Subscribe. Evidence: `PlayerPresentation.kt:114–127` reads neither `now.buffering` nor `now.error`; Play/Pause depends only on actual `now.playing`. Loading audio is displayed only inside Now Playing at line 161. `AddPodcastsScreen.kt:83–97` disables Subscribe while its request runs but leaves its label unchanged and supplies no per-request spinner. Find’s busy bar is controlled by a different `busy` flag. **Fix:** show indeterminate progress on the mini Play control while buffering, and a per-result Subscribing indicator; retain stop/cancel where appropriate. This is absence of progress rendering in source, not a measured response-time failure.
- **F05 · DATA-04 — no general multi-step Undo/Redo.** Where: View edits, Playlist name/settings, marks and reorder. Evidence: `ScreenActions.kt:144–149` replaces a single `latestUndo` closure and clears it after use; PlayerContainer collects the latest message and shows one snackbar. `recordUndo` restores edits without creating a general redo transaction. The explicit resubscribe toggle is a local exception, not an app editing history. **Fix:** retain a bounded transaction history with logical edit coalescing and named Undo/Redo access suitable for a phone. Keep the existing snackbars and Trash; do not replace them with confirmations.
- **F06 · DRAG-06 — drop does not retain the moved Entry’s selection/focus.** Where: Playlist Entries reorder. Evidence: `EntryDragging.kt:103–108` commits MoveEntry and immediately clears `drag.source`/boundary; line 75 makes that source the only drag highlight. `AppModel.kt:101–114` offers Undo but establishes no destination focus/selection/reveal. Edge autoscroll at EntryDragging lines 57–68 is present and earns credit. **Fix:** keep a destination Entry key and visible selected/focused state after drop, reveal it if necessary, and announce the result. No claim of a failed live drag or frame-rate problem is made.
- **F07 · COPY-02 — failures are hidden from the current task surface.** Where: collapsed playback and Standalone Library/Subscription refresh. Evidence: `PlaybackService.kt:263–274` sets error and pauses after exhausting sources; MiniPlayer never renders error/recovery, while `PlayerPresentation.kt:160` provides it only after expansion. `apps/android/data/src/main/kotlin/app/podlist/data/LibrarySource.kt:94–121` catches per-feed refresh failures and stores `feed_state.last_error`; the Android UI never reads that state, and `AppModel.kt:332–335` keeps Standalone status Ready. **Fix:** deliver a playback error with Retry playback where Play was invoked (for example, the existing snackbar region), and expose per-Subscription refresh failure plus Retry/last successful refresh. Keep the compact player free of visible podcast/Episode names. Error handling must not require guessing that opening another surface will reveal it.

**Minor**

- **F08 · FLOW-05 — peer stats tiles have ragged bottoms at 200%.** Where: Time listened and Episodes finished. Gesture smoothness and physical feel remain N/O.
- **F10 · COPY-01 — recovery action names the wrong operation.** Where: OPML error and failed resubscribe/import Undo. Evidence: `strings.xml:27` defines the shared `retry` resource as “Retry sync”; `SettingsScreen.kt:50` binds it to `actions::retry`, which repeats file read/import/export; `AppModel.kt:202` uses it for subscription recovery. **Fix:** add operation-specific Retry import/export/Subscribe labels, or a genuinely generic Retry; reserve Retry sync for synchronization.
- **F11 · COPY-03 — several empty task states omit a next step.** Where: History, Listening Timeline, Subscription Episodes. Evidence: S13 and `PlaybackActions.kt:37`, `TimelineScreen.kt:23`, `PodListScreens.kt:293–295` show only no-history/no-listening/no-Episodes text; compare the useful Find Episodes action in empty Entries and Play an Episode instruction in empty stats. **Fix:** explain “Play an Episode from Entries to start this Timeline” / “Finish an Episode here to build History”, with a route to Entries; for an empty Subscription, explain refresh/publisher status and provide an appropriate retry when needed. An empty Trash needs no contrived creation action and is not part of this failure.
