# PodList Mac UI grade · Round 22 · Codex

## Frame

- **Task** — Find an Episode in Subscriptions, a saved View or Search, queue it in a Playlist, and play or resume it without losing the Library context.
- **Target** — Native SwiftUI/AppKit Mac app, macOS 26+, at `2e8917fee39e4cec4fdce0223e4533cc997668be`.
- **Era** — Current build, macOS 26.0 SDK and deployment target, no design compatibility opt-out. VM ran macOS 27.2 (26B123) at 1920 × 1200 pt, 2×. App Appearance was set to Light or Dark. Reduce Transparency and Increase Contrast were off. Show Borders was off for the main tour and on for a separate pass.
- **Posture** — Sovereign personal Library with background playback and a modeless podcast discovery panel.
- **Audience** — Perpetual intermediate listener who returns to established Views and Playlists.
- **Nearest exemplar** — Things 3 for a persistent source list, named Undo and a compact command vocabulary. Apple Podcasts on the same release is the visual reference for the sidebar, player and Settings. [Exemplars](/Users/sarvagnan/Documents/UI_Guidelines/guidelines/exemplars.md) · [Apple reference captures](/Users/sarvagnan/Documents/UI_Guidelines/examples/screenshots/README.md)
- **Character** — Compact, two-line Episode rows with aligned duration and state. A Playlist keeps its own Entries, History, Timeline and position. Artwork or initials anchor the Inspector and player. Owner-fixed elements include the Multicolor brand blue and the glass transport bar, Inspector controls, Now Playing and scrolling-sheet footers. Baseline captures are 01–03, 06–09, 18 and 35 in both appearances. [Light baseline](/Users/sarvagnan/Documents/PodcastClient/podlist-grading/mac-round-22/light/03-episode-inspector.png) · [Dark baseline](/Users/sarvagnan/Documents/PodcastClient/podlist-grading/mac-round-22/dark/03-episode-inspector.png)
- **Owner decisions** — Score the fixed treatment of the Dark Settings label, the noncustomizable toolbar and grouped Playlist actions, the redundant entry points for Play, the narrow pane swap and remembered default Inspector width, and the wide selection-driven Inspector. Preserve the Saved Views menu name, page-only two-click Unsubscribe, location-scoped inline Undo, no automatic navigation for an undone View or empty Playlist, the deleted Settings state and the selected-row Timeline action. Sidebar and New Playlist response misses are accepted. Spotlight and donations are build-gated, App Intents are available, and MCP is opt-in. ## Checklist

Coverage: **93.3%** (pass 127 · fail 13 · N/O 10 · N/A 19)

### Blockers

- **MENU-02** — A failed Episode drop row can retry that one Episode. The Episode menu's `Retry Failed Episode Drop` invokes batch recovery across all failed drops, including other Playlists. There is a selected-failure Remove path, but no selected-failure Retry equivalent. With two failures the same scope is unavailable from the menu. Fix by adding **Retry Selected Episode Drop** to Episode, driven by the focused failed row's ID and the existing per-row handler. Name the existing batch action **Retry All Failed Episode Drops** and keep both visible with scope-appropriate validation. Capture 06 shows the Entries surface. The failure branch is code-derived. [Row recovery](../../apps/apple/Sources/PodListUI/PlaylistContentView.swift#L148) · [Batch recovery](../../apps/apple/Sources/PodListUI/EpisodeTransfer.swift#L176) · [Menu registry](../../apps/apple/Sources/PodListUI/MenuCommandActions.swift#L150) · [Menu capture](/Users/sarvagnan/Documents/PodcastClient/podlist-grading/mac-round-22/menus.txt)

## Next step

**Between this build and 9.0.** The command index needs scope parity first. Then Inspector and Settings need a reliably visible response within 200 ms, and Light Library subtitle contrast needs correction. The Dark Settings accent is an accepted ceiling under this rubric. With it still a major, Color & contrast stays at 6.9 and Overall ultimately stays at or below 8.9. The missing live measures for Full Keyboard Access, scrolling, continuous input and live resizing limit the claims of polish.

**Target — MENU-02.** The root cause is the menu's recovery registry taking the aggregate retry closure while the per-row handler has the exact failed slot identifier. It is the command-discovery gap illustrated by PLAT-01. Follow Things' selected-object command model and expose **Retry Selected Episode Drop** in Episode while a failed row owns selection. Keep **Retry All Failed Episode Drops** as the broader menu command. Bind the selected item to the same handler as the row, keep validation visible and disabled when inapplicable, and test two failed Episodes in different Playlists with one selected. Only that Episode should retry through the selected command. Expected effect is a complete keyboard/menu recovery route and removal of the Platform fit blocker while preserving direct row recovery. The extra menu item is the tradeoff. [PLAT-01 reference](/Users/sarvagnan/Documents/UI_Guidelines/examples/contrasts.md#plat-01--menus-are-the-complete-command-index)
