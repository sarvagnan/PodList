# Rewind undoes playback, not edits

Each Playlist keeps a 30-day Listening Timeline so the user can Rewind to a remembered moment — typically after falling asleep while playback ran on, finishing Episodes (marking them Played and triggering Clear on Played) and advancing the Cursor. A Rewind reverses only what playback did since that moment, in that Playlist; edits the user made deliberately (adds, reorders, Episodes marked Played by hand) survive. This means every Played fact must record whether it came from playback (and from which Playlist) or from the user, from day one — it cannot be reconstructed later. We rejected restoring a full Playlist snapshot because it would silently discard intentional changes. Rewind is an ordinary sync operation (ADR 0003). Helping the user *find* the moment (search, previews, transcripts) is out of scope; v1 presents the Timeline as a plain list.
