# Playlists are stored as documents, with index tables for Views

The shared SQLite schema (`packages/domain/src/Sql.ts`) is relational for the Library catalogue (Subscriptions, Episodes) because Views query it, but stores each Playlist and each View whole, as JSON, and mirrors only what Views filter on into small index tables (`episode_state`, `entry_index`). The domain reducer works on whole Playlists — Entries, Cursor, History and Listening Timeline together — so reading and writing one row per Playlist keeps persistence a straight mapping of `State` and avoids keeping an ordered entry table, a history table and a timeline table consistent by hand. The cost is that a Position report rewrites that Playlist's document; with the Timeline sampled at most once a minute and kept 30 days, a document stays in the hundreds of kilobytes even with heavy listening. The index tables are derived and can always be rebuilt from the documents.
