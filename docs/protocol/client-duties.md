# Client duties

This is the implementation order and observable behavior for clients using protocol version 4. “Shared” means every client must preserve the contract. “Offline clients” means the planned Kotlin and Swift clients and Electron. “Browser adapter” identifies existing web implementation details which native clients should implement through platform APIs. The currently shipped web client still uses local SQLite and offline behavior; the online-only web client in ADR 0011 has not been implemented. Do not build against planned server read APIs: they do not exist yet. [Sources: platform plan](../plans/platform-clients.md), [ADR 0011](../adr/0011-a-client-per-platform-and-an-online-only-web-client.md), [API definitions](../../packages/api/src/index.ts), [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts).

## 1. Establish the Device and connection

Shared: reach the single-user server through the user's Tailscale tailnet. There is no application login, bearer token, cookie or API key. Use the server origin plus the `/api` paths in [openapi.json](../../packages/domain/protocol/openapi.json). GET `/api/health` reports `protocolVersion` (currently 4) and optionally the deployed release. The existing client does not negotiate or reject mismatched versions automatically; do not infer a version-upgrade handshake. [ADR 0004](../adr/0004-tailnet-is-the-auth-boundary.md), [System.ts](../../packages/api/src/System.ts), [Http.ts](../../packages/server/src/Http.ts), [Transport.ts](../../packages/web/src/sync/Transport.ts).

Offline clients: create and durably store one opaque Device id for this installation, and reuse it after restarts. Before the first push or pull, POST `/api/devices` with id, nonempty name, kind and `registeredAt` in UTC epoch milliseconds. Persist successful registration; retry after failure. Registration by an existing id updates name and kind, preserving the original stored registration time. The server does not enforce registration before push, but the client workflow does it first. Device.kind currently accepts only `pwa` and `desktop`, and the existing SyncEngine sends `pwa` even when used by Electron. **Native kind values require an owner decision; this phase does not invent or add them.** [Device.ts](../../packages/domain/src/Device.ts), [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts), [SyncStore.ts](../../packages/server/src/SyncStore.ts).

## 2. Persist edits and synchronize

Offline clients: make each State edit an Operation with a unique stable id, this Device id, a persistent increasing `sequence` starting at zero, `recordedAt` from this Device's clock, and a schema-valid change. In one local transaction, append it to a durable ordered outbox, advance the sequence, apply it optimistically, and persist State and indexes. Notify the UI and request sync after commit. Never regenerate ids when retrying. Keep confirmed server State separately from optimistic State. Missing targets are dropped by the rules, rather than turning into errors. [Operation.ts](../../packages/domain/src/Operation.ts), [State.ts](../../packages/domain/src/State.ts), [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts), [StateStore.ts](../../packages/domain/src/StateStore.ts).

Perform a full sync in this order:

1. Register the Device if not registered. Snapshot the outbox in local sequence order. If nonempty, POST `/api/sync/push` with those exact operations. `accepted` counts previously unseen input ids; retries can legitimately return zero. Do not use the push cursor as the pull cursor: other Devices' earlier operations would be skipped. [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts), [SyncStore.ts](../../packages/server/src/SyncStore.ts).
2. GET `/api/sync/pull?since=<last-user-cursor>` (zero initially). A nonpositive cursor yields the entire State as `snapshot` and no operations. Otherwise, replay returned operations in server order against confirmed State. Use a non-null snapshot as the confirmed State directly. The server returns all remaining operations without paging. Server intentions needing the Library are already expanded in that operation stream. [Sync.ts](../../packages/api/src/Sync.ts), [SyncStore.ts](../../packages/server/src/SyncStore.ts).
3. In one local transaction after a successful pull, remove only outbox entries in the sent snapshot, save confirmed State and the pull cursor, then rebuild optimistic State as confirmed plus all still-pending operations. Preserve edits recorded during network calls. A failed push or pull leaves pending work for retry, even if the server accepted a push whose response was lost. Deduplication by operation id prevents double counting Listening log amounts. [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts), [State.ts](../../packages/domain/src/State.ts), [SyncStore.ts](../../packages/server/src/SyncStore.ts).
4. Independently GET `/api/library/changes?since=<last-Library-cursor>` (zero initially). Atomically upsert each page of Subscriptions and Episodes by id and persist that page's returned cursor. Repeat while `more` is true. Default page size is 500; the HTTP handler caps a supplied limit at 2000. Upsert Subscription rows before Episode rows, preserve the user's State, and notify readers so Views re-evaluate. The cursor can advance by more than the row count; use the returned value. This stream reports inserts and updates, including Unsubscribe and Subscription overrides, without deletion tombstones. State can arrive before Episode metadata, so a missing Episode's details are temporary until the Library pull completes. [Catalogue.ts](../../packages/server/src/Catalogue.ts), [Http.ts](../../packages/server/src/Http.ts), [client Library upserts](../../packages/web/src/sync/Catalogue.ts), [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts), [Playback.ts](../../packages/web/src/playback/Playback.ts).

Offline clients should preserve the current triggers using platform lifecycle/network callbacks: sync immediately on startup, after edits, when connectivity returns, when the client becomes visible/foreground, and periodically while running. The existing scheduler waits for an edit/network/visible trigger or a one-minute timeout, waits two seconds for the burst to settle, clears queued triggers, then syncs. This is a timeout after the preceding sync, not a fixed wall-clock schedule. It coalesces triggers rather than running a request for every edit. [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts).

On transport failure, keep local edits and downloads usable, retain pending operations and both cursors, expose the sync error, and retry on the next trigger/periodic pass. If State sync succeeded but Library sync failed, keep the committed State sync and resume Library paging from its last committed page. There is no exponential retry backoff in SyncEngine and no special conflict-status protocol. The browser transport maps request/decode failures to Offline. Discovery, Subscribe, Unsubscribe, OPML import, refresh and uncached Chapter resolution need the server; these are HTTP requests, not queued State operations. [SyncEngine.ts](../../packages/web/src/sync/SyncEngine.ts), [Transport.ts](../../packages/web/src/sync/Transport.ts), [LibraryClient.ts](../../packages/web/src/library/LibraryClient.ts), [API definitions](../../packages/api/src/index.ts), [SyncIndicator.tsx](../../packages/web/src/components/shell/SyncIndicator.tsx).

Browser adapter only: DOM `online` and `visibilitychange` callbacks drive the above triggers. The present web build also uses a single-tab database lock, a service worker, and OPFS. Those are not native requirements. The later online-only web client will use server APIs and tab coordination instead. [TabGate.tsx](../../packages/web/src/app/TabGate.tsx), [TabLock.ts](../../packages/web/src/platform/TabLock.ts), [main.tsx](../../packages/web/src/main.tsx), [DownloadStore.ts](../../packages/web/src/platform/DownloadStore.ts), [ADR 0011](../adr/0011-a-client-per-platform-and-an-online-only-web-client.md).

## 3. Report Position and Played

Shared: Position is per Entry, not per Episode. Use the Active Playlist's Cursor and Entry Position when loading. Switching Playlists resumes its own Cursor. The current Device keeps its loaded Episode while playing (and while holding an Episode already Played but not ended), even if sync changes the Active Playlist/Cursor; paused playback follows State again. Global Playback Settings apply with per-Subscription keys overriding only the keys present. A speed change in the player applies only to the currently loaded Episode; it does not save Playback Settings. [Playback.ts](../../packages/web/src/playback/Playback.ts), [playbackSettings.ts](../../packages/web/src/lib/playbackSettings.ts), [PlaybackSettings.ts](../../packages/domain/src/PlaybackSettings.ts).

Shared reporting behavior: while playing, report on a Position event if at least 15 seconds have passed since the preceding report. Also flush on pause, before changing the loaded Entry, before and after an explicit seek, before speed changes, on finishing and audio end, and when the app is hidden/leaves the page. Use the platform background/lifecycle equivalents in native clients. A report with less than one second of Position movement is suppressed unless it has pending listening amounts. Seek clamps to zero and known duration, flushes preceding listening, resets the measurement boundary and reports the new Position without counting the seek. `listenedAt` is the reporting Device's current epoch milliseconds; strictly newer listen time wins, and equal listen time uses arrival order. Timeline sampling is separately limited to one minute per Episode. Browser lifecycle flushing is best effort, not a guaranteed upload at shutdown. [Playback.ts](../../packages/web/src/playback/Playback.ts), [State.ts](../../packages/domain/src/State.ts), [TimelineRules.ts](../../packages/domain/src/TimelineRules.ts).

On a Position event, mark Played once Position is at least `max(0, duration - threshold)`; threshold is the Subscription override or 30 seconds if null. Zero override means reaching the end, not using the default. Unknown duration cannot finish by this check; audio Ended still finishes. Very short Episodes can satisfy the threshold at Position zero. Send the last Position/listening report before MarkPlayed with source `{ "_tag": "Playback", "playlistId": "…" }`. Clear on Played, History and Cursor changes follow the shared rules. Continue the last seconds of this Episode after it becomes Played; do not immediately start the next Entry at the threshold. Once the actual end or skip-outro boundary is reached, advance to the Cursor's Entry unless the sleep timer stops playback. Intro/outro skipping uses global/Subscription Playback Settings. [PlayedRules.ts](../../packages/domain/src/PlayedRules.ts), [Playback.ts](../../packages/web/src/playback/Playback.ts), [Listening/threshold vectors](../../packages/domain/protocol/listening.json).

After Played, the Entry may be removed or reset. Do not send subsequent Position reports that move it back into the Episode; send pending listening using RecordListening until the loaded Episode ends. MarkPlayed from a person uses source User, which creates no History. MarkUnplayed clears the Episode fact without restoring removed Entries. [Playback.ts](../../packages/web/src/playback/Playback.ts), [PlayedRules.ts](../../packages/domain/src/PlayedRules.ts), [State.ts](../../packages/domain/src/State.ts).

## 4. Measure and report the Listening log

Shared: count listening only between Position events while playing. For before/after samples, compute elapsed wall seconds and forward audio Position delta divided by the current speed. Reject nonpositive elapsed, gaps over 30 seconds, nonpositive progress, invalid speed, or progress greater than elapsed plus one second of jitter. Otherwise count `min(elapsed, progress)` seconds. A forward seek small enough to fall inside the jitter tolerance is indistinguishable from listening unless the Player emits a discontinuity. Paused Position events never count. A Playing event seeds the boundary with the current Position and clock time. Pause, failure, explicit seek, Player discontinuity (including buffering and external seeking/rate changes), speed change and loading another Entry clear the boundary. After clearing, the first Position event while playing establishes it without counting, unless a Playing event has already seeded it. [Listening.ts](../../packages/domain/src/Listening.ts), [Playback.ts](../../packages/web/src/playback/Playback.ts), [Player.ts](../../packages/web/src/platform/Player.ts).

Until the Episode row supplies a Subscription id, Position events do not contribute listening amounts. Attribute accepted seconds to the loaded Episode's Subscription and the listening Device's local calendar date. Take its UTC-minus-local offset at the ending sample. Attribute accepted time to the interval ending at that sample (`end - acceptedSeconds` through `end`); split at local midnight using that offset. Exactly ending at midnight contributes to the preceding day only. Capture the day string `YYYY-MM-DD` on the Device; never reinterpret it using the server timezone on replay. No timezone name is stored. If an offset changes between samples (travel or daylight saving), the ending offset applies to the whole interval; no historical timezone transition is reconstructed. Wall-clock jumps are subject to the same gap/jump rejection. [Listening.ts](../../packages/domain/src/Listening.ts), [Playback.ts](../../packages/web/src/playback/Playback.ts), [measurement vectors](../../packages/domain/protocol/listening.json).

Accumulate pending amounts by day and Subscription, attach them to ReportPosition, and clear them only by durably recording that operation locally. After Played use RecordListening. Distinct Devices contribute independently, including simultaneous listening; retries reuse operation ids. A stale Position, removed Entry or removed Playlist does not discard listening amounts. Rewind, Unplayed and Trash expiry never subtract listening time. Do not backfill Listening log from History or Timeline; a crash can lose the unreported tail. [Playback.ts](../../packages/web/src/playback/Playback.ts), [State.ts](../../packages/domain/src/State.ts), [Listening.ts](../../packages/domain/src/Listening.ts), [ADR 0010](../adr/0010-permanent-listening-log.md).

For Listening stats, time listened is permanent, but Episodes finished is the current Playback-source Played facts for Episodes with a stored Episode row, grouped by Played date, excluding manual marks. The screen checks row existence without applying View Library visibility, so retained rows of removed Subscriptions can still count; the ADR calls this “still in the Library”, which needs clarification. Unplayed and Rewind can reduce that count. Weeks start Monday; a Listening streak may end today or yesterday. Periods use the viewing Device's calendar. Weekly/monthly totals exclude dates later than today, while all-time time listened and top podcasts include amounts already reported by a Device on tomorrow's date. [Listening.ts](../../packages/domain/src/Listening.ts), [data.ts](../../packages/web/src/app/data.ts), [listening-stats.tsx](../../packages/web/src/routes/listening-stats.tsx), [ADR 0010](../adr/0010-permanent-listening-log.md).

## 5. Select audio sources

Shared: prefer a stored download on this Device. Otherwise use the Episode's `audioUrl` from the local Library, with `/api/episodes/{id}/audio` as the server fallback. Direct streaming must work when the server is unreachable but the podcast host is reachable. If the Library row has not arrived, the current implementation uses the proxy URL until the Episode metadata arrives. Keep Position and speed when trying a fallback, and try each candidate once per load. Report an error after all candidates fail; explicit retry starts a fresh load at the current Entry Position. [ADR 0009](../adr/0009-stream-direct-from-podcast-hosts.md), [runtime.ts](../../packages/web/src/app/runtime.ts), [Playback.ts](../../packages/web/src/playback/Playback.ts), [Player.ts](../../packages/web/src/platform/Player.ts).

The browser adapter's exact candidate order is:

| Input | Candidates in order |
| --- | --- |
| Stored `blob:` URL | Stored URL only, with requested Volume Boost |
| No distinct proxy URL | Input URL only, with requested Volume Boost |
| Direct URL, Volume Boost off | Direct without boost, then proxy without boost |
| Direct URL, Volume Boost on | Proxy with boost, then direct without boost |

Each source gets a fresh audio element. Preserve Position and rate on fallback after media error, non-autoplay play rejection or a ten-second loading timeout while play is wanted. A browser NotAllowedError does not switch sources; user interaction is needed. HTTP media on an HTTPS page can fail as mixed content, advancing to the proxy by the same error path. **The proxy-first Volume Boost exception is web-specific:** Web Audio can silence cross-origin audio without CORS, so the direct fallback uses a fresh element without boost and explains “Playing directly without Volume Boost.” Native audio engines need not route through the server just to boost volume. [Player.ts](../../packages/web/src/platform/Player.ts), [ADR 0009](../adr/0009-stream-direct-from-podcast-hosts.md).

For downloads, try the host URL first, then the server proxy on CORS/transfer failure (skip repeating an identical URL). Commit only complete files; incomplete transfers must not appear as stored downloads. Electron uses its private `app://podlist/audio-download` main-process HTTP(S) route to perform downloads without changing other origins' CORS or disabling renderer web security. OPFS, blob URLs, browser persistent-storage requests and this Electron bridge are adapters, not native requirements. [Downloads.ts](../../packages/web/src/downloads/Downloads.ts), [DownloadStore.ts](../../packages/web/src/platform/DownloadStore.ts), [desktop main.ts](../../packages/desktop/src/main.ts), [ADR 0009](../adr/0009-stream-direct-from-podcast-hosts.md).

The server audio proxy looks up the Episode id, follows that Episode's host redirects, forwards Range/If-Range and conditional request headers, and passes through status/body and selected audio/cache headers. It is not an arbitrary URL proxy. Use the generated OpenAPI for parameters, response schemas, refresh, Chapters, Directory, OPML and Artwork endpoints. Artwork proxy accepts only HTTP(S) Artwork in the Library (or its cache) and returns resized WebP. [Media.ts](../../packages/server/src/Media.ts), [Artwork.ts](../../packages/server/src/Artwork.ts), [OpenApi.ts](../../packages/api/src/OpenApi.ts).

## 6. Apply this Device's Download Rules

Offline clients: Download Rules are keyed by Subscription and Device; never execute another Device's rule. No rule means Stream (`never`), which fetches nothing. Unsubscribe does not itself remove downloads on any Device. `onEntry` fetches Unplayed Episodes that are an Entry in any Playlist outside Trash. `allNew` does that too, plus Unplayed Episodes whose Published time is at least this Device's local `ruleSince`, newest Published first, limited by `keepAtMost` if non-null. Entry downloads are outside that cap. The existing adapter persists `ruleSince` when it first sees an `allNew` rule for that Subscription, and does not reset it on later mode changes. It is local metadata, not a synced timestamp. There is no explicit secondary ordering on equal Published times for this cap. [Device.ts](../../packages/domain/src/Device.ts), [Subscriptions.ts](../../packages/server/src/Subscriptions.ts), [DownloadRules.ts](../../packages/web/src/downloads/DownloadRules.ts), [plan.ts](../../packages/web/src/downloads/plan.ts).

A rule-owned stored download is discarded when no rule wants it (for example Played, no longer an Entry under `onEntry`, or outside the `allNew` cap). A Starred Episode's stored download is never automatically discarded. Manual Downloads are outside all rule cleanup and caps; only explicit removal deletes them. A Star does not itself request a download and does not prevent Clear on Played. `allNew` can retain an Episode with no Entry, so the domain shorthand “discarded once no longer an Entry” is not an unconditional rule for `allNew` or Manual Downloads. [plan.ts](../../packages/web/src/downloads/plan.ts), [Downloads.ts](../../packages/web/src/downloads/Downloads.ts), [PlayedRules.ts](../../packages/domain/src/PlayedRules.ts), [CONTEXT.md](../../CONTEXT.md).

The current worker reacts to State/download-status changes, debounces one second and starts at most two transfers concurrently. Although its comment mentions Library changes, it does not subscribe to Library invalidation directly: a new Episode arriving without a State/status emission can wait until the next such emission. Failed downloads remain failed until cancellation/explicit retry; rule evaluation excludes Episodes already in the status map. These are current adapter limitations for the owner to resolve, not reasons to silently change contract vectors. Native scheduling can use platform background download services; preserve selection, caps, Star protection and Manual Download ownership. [DownloadRules.ts](../../packages/web/src/downloads/DownloadRules.ts), [Downloads.ts](../../packages/web/src/downloads/Downloads.ts), [DownloadStore.ts](../../packages/web/src/platform/DownloadStore.ts).

## Owner decisions before native implementation

Agree native Device.kind values and whether to retain the current edge behavior: ASCII-only Mentions folding, future Published matching LastDays, equal-time Position tie handling, no positive In a Playlist filter, tied Published ordering in Subscription expansion/download caps, and `ruleSince` surviving mode changes. The measurement contract uses the ending timezone offset for a whole sample interval and accepts unannounced small seeks within one second of jitter. Those limitations are preserved and documented, not hidden in a newly invented rule. The Download Rule worker's missing direct Library trigger is tracked as follow-up work.
